# D006 — One file per decision, finding and work item

Date: 2026-08-10

## Decision

Decisions, specs, findings and open work each get their own directory with one
file per item, not one append-only log per category:

    docs/decisions/D00N-<slug>.md
    docs/specs/<topic>.md
    docs/findings/YYYY-MM-DD-<slug>.md
    docs/not-fixed-yet/NF-00N-<slug>.md

Each directory has an `INDEX.md` generated by `tools/docs-index.sh` and verified
by the pre-commit hook, so an index can never drift from its directory.

## Why

A shared append-only file is a merge conflict waiting to happen, and it makes the
one operation this project needs constantly — "show me everything about NF-004" —
into a search through unrelated text. Separate files mean an item's whole history
is one path, `git log` on it is meaningful, and two sessions working different
items do not touch the same bytes.

The generated index is what makes the split navigable: an agent reads one file to
see the whole queue and its statuses.

## Alternatives rejected

- **Single `decisions.md` / `findings.md` appended to.** Simpler to write, worse to read, and conflicts under any parallel work.
- **Issue tracker.** The point is that everything needed to continue lives in the checkout.

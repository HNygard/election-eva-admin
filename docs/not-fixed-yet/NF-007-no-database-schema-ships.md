# NF-007 — No database schema ships with the release

Status: FIXED
Milestone: M2

## Symptom

The application expects an existing PostgreSQL schema. Nothing in the release
creates one: no `.sql` migrations, no `hbm2ddl`, no
`javax.persistence.schema-generation` property anywhere.

## What is known

`flyway-maven-plugin` 4.2.0 is configured in the root pom's `pluginManagement`,
so the real schema came from Flyway migrations — which lived in the unpublished
`admin-other`/`admin-docker` modules.

D005 decides the schema is regenerated here from the release's own entity
classes, into `docker/postgres/initdb/01-schema-generated.sql`.

`~/git/eva-admin-spring-boot-hacktogether` did this once already, from copies of
these same entities, and produced 113 tables and 176 foreign key constraints. Use
it as a cross-check, not as a source.

## How to approach

Build the export tool under `tools/schema-export/`. It needs M1's artifacts
installed in the Maven volume first. It should reuse the entity list from
`admin/admin-backend/src/test/resources/META-INF/persistence.xml` rather than
restating 118 class names, so it cannot drift; the release file stays unmodified
and is only read.

Then generate, apply via `docker/postgres/initdb/`, and compare table and
constraint counts against the sibling repo. Investigate any difference.

Read D005's "known limits" section before trusting the result: no seed data, view
entities become plain tables, no sequences.

## Done when

`docker compose -f docker/postgres/docker-compose.yml up` produces a populated
schema from a file generated by this repo, and the generated file is committed and
declared `GENERATED`.

## Resolution

`tools/schema-export/generate.sh` produces
`docker/postgres/initdb/01-schema-generated.sql` from the release's own entity
classes, and PostgreSQL loads it: **113 tables, 176 foreign keys**, all in the
`admin` schema. That matches the sibling repo's independent derivation exactly,
table name for table name.

One correction came out of it, and it changes NF-006: the entity list must come
from the `@Entity` annotations in the source, not from any shipped
`persistence.xml`. None of them covers the whole model — 117 in the admin-backend
test unit, 119 across all of them, 120 in the source.

See `docs/findings/2026-08-11-schema-generated-from-entities.md`.
